Status: implemented · Issue: #203 · Date: 2026-10-27

## In short

The booking page shows every available appointment time for the selected day. Its filter row contains Specialty, Date, and Doctor only.

## How it works

The GET form no longer renders or submits a time range. The booking page requests the full day's slots and uses the full-day range for the day availability counts. Links between days and booking form fields no longer carry time parameters. The JavaScript still submits the GET form when Specialty or Doctor changes.

## Main design choice

Ignore old `from` and `to` query parameters instead of preserving a hidden time range. This makes older links show the same complete day as a new visit. The existing slot model and its optional range arguments remain available to other callers.

## Problem and constraints

The separate time control used space in a filter row where the day's appointment times already fit on screen. The base app uses server-rendered PHP and vanilla JavaScript, and the GET form must work with JavaScript disabled.

## Alternatives considered

- Hide the control but keep reading its query parameters: rejected because an old link could silently hide available slots.
- Remove optional range support from the slot model: rejected because this issue concerns the booking page, and other callers may still need that API.

## Trade-offs

The page can no longer narrow a long day to a short time range. Patients can see and choose every remaining appointment on the selected date.

## Key parameters

- Day availability uses the existing model range `00:00` through `23:59`.
- The seven-day browsing window remains unchanged.

## Assumptions

The booking grid is short enough to scan without a time-of-day filter at desktop and mobile widths.

## Edge cases

- An old URL containing `from` or `to` still renders the full day.
- Specialty and Doctor changes still submit the GET form with JavaScript; the noscript button works without it.
- Rescheduling uses full-day availability to choose its landing day.

## Breaks or needs follow-up

None.

## Traps

- Do not pass legacy time query parameters into the slot query or day links; that would recreate a hidden filter.
- Keep the selected date and pinned reschedule doctor when changing filters.
- Do not remove the booking model's optional time-range arguments as part of this page change.

## Components

- `clinic-base/book.php` removes the time control and requests full-day availability and slots.
- `clinic-base/assets/booking-slots.js` removes the now-unused time-input listener.
- `tests/test_book_page.php` checks that the time fields and legacy query reads are absent.
- `tools/ui/issue203.test.mjs` checks full-day slots and remaining filters at 1280 and 390 pixels with JavaScript on and off.
- Existing booking browser tests are updated to exercise the remaining controls.

## Changes outside the scope

The PHP and browser tests and this decision record are verification artifacts. No other application page or stylesheet changed.

## How it was verified

The issue browser test checks the full-day slot count, removed controls, date links, filter submission, noscript submission, and viewport width at both requested sizes. The PHP suite checks the booking behavior. Before and after screenshots are under `UIPROBLEMS/after/iter8/issue203-time-filter/`.

## Not verified

The browser test does not complete a booking transaction; the PHP suite covers booking transactions.

## To change this

If a time filter becomes necessary again, add a visible control and keep the slot query, day counts, and day links in sync.

## Rollback

Restore the time inputs, query parsing, matching day links, and listener together with their prior tests.
