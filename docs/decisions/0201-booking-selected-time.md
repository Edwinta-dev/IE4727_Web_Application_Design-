Status: implemented · Issue: #201 · Date: 2026-10-27

## In short

The booking confirmation now shows the selected slot's time and date. Before a slot is chosen, it asks the patient to select one.

## How it works

`book.php` accepts a `slot_id` from the query only when it belongs to the currently visible, available slots. It renders that slot's formatted time and date into the confirmation and marks the matching time and doctor radios checked. Each available time radio carries the same display text in `data-time`. `booking-slots.js` copies it into the confirmation when a time or doctor selection changes.

## Main design choice

Render the same formatted slot label in PHP and in each slot radio's `data-time` attribute. Existing vanilla JavaScript copies that label into the confirmation when selection changes. This uses the current server-rendered grid instead of adding a request or a second client-side date formatter. PHP resolves a `slot_id` query parameter only against currently bookable slots, so an unavailable or unrelated ID cannot prefill the summary.

## Problem and constraints

The confirmation showed the literal placeholder after choosing a time. The base app permits only server-rendered PHP and vanilla JavaScript, and the booking form must keep its existing slot and doctor submission behavior. Query-prefilled selection must also render without JavaScript.

## Alternatives considered

- Format the date in JavaScript from the slot timestamp: rejected because it duplicates PHP formatting and can shift the date through timezone parsing.
- Put the selected time in a new form field: rejected because the existing radio already identifies the slot and adding another submitted value can disagree with it.

## Trade-offs

The short formatted label appears in the rendered summary and in each available radio's attribute. This repeats presentation text but keeps server rendering and client updates identical without an extra request.

## Key parameters

- `slot_id` is accepted for prefill only when its string ID matches an available slot in the current doctor, date and time filters.
- `data-time` and `#selected-time` display the selected time as `h:mm AM/PM (D, j M)`.

## Assumptions

The visible slot list is authoritative for prefill. A link to a slot outside the current filters leaves the confirmation unselected.

## Edge cases

- An invalid, unavailable or unrelated `slot_id` leaves the prompt visible.
- In the all-doctors view, several slot IDs may share a time cell. The server checks the time cell and the selected doctor; the existing JavaScript maps the submitted radio value to that doctor's slot.
- With JavaScript disabled, a single-doctor query prefill still shows the selected time.

## Breaks or needs follow-up

None.

## Traps

- In the all-doctors view, one time cell can represent several doctors. The checked radio is matched by `SlotDateTime`, while the selected doctor radio identifies the exact slot; the existing JavaScript maps its submitted value to that doctor's slot.
- Keep the date in the displayed label so the confirmation identifies the complete appointment time. Keep escaping both the attribute and visible text with `e()`.
- Do not require JavaScript for the query-prefilled readout; it renders in PHP too.

## Components

- `clinic-base/book.php` resolves the selected slot and renders the label and empty prompt.
- `clinic-base/assets/booking-slots.js` updates the label after each slot change.
- `tools/ui/issue201.test.mjs` exercises selection, query prefill, empty state, and no-JavaScript rendering in Chromium at desktop and mobile widths.
