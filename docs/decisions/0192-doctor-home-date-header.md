Status: implemented · Issue: #192 · Date: 2026-10-16

## In short
The displayed schedule date sits between Previous day and Next day, centered over the appointments at desktop and phone widths.

## Problem and constraints
The date heading was left aligned below a separate row of day links. The issue asks for the date and adjacent controls to read as one centered group above the schedule. The page must keep its existing GET date filter and work without JavaScript.

## Main design choice
Move the existing day navigation into the schedule section and place its two day links around the date heading. A three-column grid gives the links equal flexible columns and keeps the heading on the schedule's center line. The optional next-appointment link or empty message remains beneath that group. This keeps the date centered even when the optional text changes, unlike centering the original flex row.

## Alternatives considered
- Center the original flex navigation row: rejected because its optional next-appointment link or empty message changes the row's width and shifts the date off the schedule center.
- Give the previous and next links fixed-width columns: rejected because the visible labels take too much room beside the date on a 390px viewport.

## How it works
The navigation group uses a bounded width and a centered grid. On narrow screens, the visible Previous day and Next day labels are hidden to leave room for the date, while the links retain accessible names and at least 2.75rem hit targets. Both links still load the existing server-rendered GET page.

## Traps
- Centering the whole old flex navigation row would also include the optional jump link or message, pulling the date away from the schedule center.
- Equal fixed-width link columns would waste space or cause overflow on a 390px viewport.
- Icon-only links need accessible names when their visible labels are hidden.

## Components
- `clinic-base/doctor/home.php`: places the date heading between the existing day links inside the schedule navigation.
- `clinic-base/assets/css/style.css`: centers the bounded date-control grid and adapts link labels for narrow screens.
- `tools/ui/doctor-home-date-header-192.test.mjs`: checks geometry at 1280 and 390 pixels and verifies both links with JavaScript disabled.

## Changes outside the scope
The browser test and this decision record are required verification artifacts. No other application page changed.

## How it was verified

The full PHP suite and PHP lint were also run.

## Trade-offs
The narrow layout displays arrows alone, so their meaning depends on their accessible labels and the adjacent date. The browser test checks their navigation behavior with JavaScript disabled.

## Key parameters
The date-control group is at most 35rem wide; the narrow controls retain a minimum width of 2.75rem.

## Assumptions
The schedule section spans the appointment table's content width.

## Edge cases
The optional next-appointment link and the empty-state message sit below the date controls and do not affect horizontal centering. The 390px check also rejects page overflow.

## Breaks or needs follow-up
None known.

## Not verified
No physical screen-reader session was run; the Chromium check verifies link names in the accessibility tree.

## To change this
If the date format becomes wider, recheck the centered grid and horizontal overflow at 390 pixels.

## Rollback
Restore the separate day navigation row and date heading styles together.
