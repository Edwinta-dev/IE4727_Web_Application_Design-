Status: implemented · Issue: #213 · Date: 2026-10-28.

## In short

The completed visit slip now identifies itself as a consultation summary, distinguishes the appointment date from the print date, and omits unverified specialty and phone details.

## How it works

When a patient opens a completed visit, the existing page renders the visit's appointment date and time, the current server date as the print date, patient and doctor details, and the saved clinical notes. A specialty row appears only when the stored value has non-whitespace content. The existing native browser print action and print layout remain in place.

## Main design choice

Keep the slip embedded in the completed visit view and correct its claims at render time. The alternative was a separate print route, but that would consume another page and duplicate the same visit data; the current view already supports printing.

## Traps

- Appointment time is not the time the page was printed.
- An empty doctor specialty must not be replaced with an invented default.
- Keep the clinic address but do not infer a telephone number.
- Print rules must use the shared display font token too.

## Components

- `clinic-base/patient/home.php`: revised title and button, consultation/print date labels, patient ID, optional specialty, sentence-case stamp, and removed phone line.
- `clinic-base/assets/css/style.css`: display token for slip headings and no uppercase/letter-spaced stamp styling.
- `tests/test_patient_home.php`, `tests/test_standout_features.php`, `tools/ui/standout-features.test.mjs`: updated expectations and regressions for revised slip copy and styles.

## Breaks or needs follow-up

None.

## Problem and constraints

The prior copy implied medical certification despite containing no certification or leave period, called the appointment timestamp an issue time, invented a specialty when none was recorded, and printed an unverified clinic phone number. The changes stay within the issue's declared scope and preserve the 11-page limit and existing print flow.

## Alternatives considered

- Leave the old date label and add an explanation: rejected because it would still describe the wrong event.
- Add a separate printable page: rejected because the embedded slip already works and the portal has a fixed page limit.

## Trade-offs

The print date is generated when the page is rendered, so a page left open across midnight retains the date from its initial load. This keeps the printable document deterministic without client-side scripting.

## Key parameters

- Appointment date/time: `appointmentDateTime`, formatted with `fmt_date()` and `fmt_time()`.
- Print date: current server date, formatted with `fmt_date()`.
- Specialty row condition: trimmed stored specialty is non-empty.
- Slip heading font: `var(--font-display)` in screen and print styles.

## Assumptions

- The server's current date is the appropriate date to show as “Printed on.”
- `$patientId` is the authenticated patient's canonical ID in this page.

## Edge cases

- Null, missing, empty, or whitespace-only specialty values omit the row.
- Dates and times remain safely escaped through `e()` after formatting.
