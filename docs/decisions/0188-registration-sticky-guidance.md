Status: implemented · Issue: #188 · Date: 2026-10-16

## In short
At desktop width, the two registration guidance sections stay in view while the account form scrolls. The narrow layout stays stacked.

## Main design choice
Make the existing guidance column sticky within the registration grid. A top offset leaves room below the header, and a viewport-relative maximum height lets the guidance scroll internally if a desktop window is short. Keeping the same column and markup avoids changing the form's reading order or registration behavior.

## How it works
The desktop media query applies sticky positioning only above the grid's 56rem breakpoint. The column remains constrained by its grid row, so it releases before the footer. At narrower widths, the existing one-column layout and normal document flow apply.

## Traps: why the obvious fix is wrong
- Sticky positioning at all widths would pin guidance below the form on a phone, consuming useful screen space.
- A sticky column without a maximum height could cut off the second section in a short desktop viewport.
- A fixed position would detach the guidance from the registration section and could overlap the footer.

## Components
- `clinic-base/assets/css/style.css`: desktop sticky offset, maximum height, and internal overflow for the existing guidance column.
- `tests/ui_registration_sticky.mjs`: Chromium checks both account roles, footer clearance, short viewport overflow, and mobile flow; it writes before and after captures.

## Breaks or needs follow-up
None known. If the header becomes fixed or changes height, review the sticky top offset.

## Problem and constraints
Issue #188 asks for the two existing guidance sections to remain visible during a long registration form. The form, page count, and server behavior must stay intact.

## Alternatives considered
- Sticky only the first section: unnecessary at the current viewport height because both sections fit.
- Independently scroll the entire form column: this would add a nested form scroll area and change keyboard scrolling behavior.

## Trade-offs
A short desktop viewport gives the guidance column its own scrollbar. The top offset is sized for the current header and must be reviewed if the shared header geometry changes.

## Key parameters
The rule starts above 56rem. The sticky offset is 4.5rem plus the shared spacing token; maximum height leaves room for the offset and a lower gap.

## Assumptions
The registration grid remains the containing block for the guidance column.

## Edge cases
Chromium checks a 1280×320 desktop viewport for internal scrolling and a 390×844 mobile viewport for normal flow.

## Not verified
Physical touch scrolling in a short desktop viewport was not tested.

## Changes outside the scope
The browser test and this decision record are required verification artifacts. No content page was added.

## How it was verified
`node tests/ui_registration_sticky.mjs` checks the layout in Chromium using `ie4727db_test` and writes captures under `UIPROBLEMS/after/iter7/issue-188-registration-sticky/`. `php tests/run.php` runs the full project regression suite.

## To change this
If the registration grid or header changes, check the support column at 1280×800, 1280×320, and 390×844 before adjusting the offset or breakpoint.

## Rollback
Remove the desktop media rule in `clinic-base/assets/css/style.css`; the existing stacked and two-column layouts remain.
