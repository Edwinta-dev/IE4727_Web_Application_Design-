Status: implemented · Issue: #204 · Date: 2026-10-27

## In short

The seven-day booking strip uses its own thin, themed horizontal scrollbar. The arrow buttons and mobile scroll instruction are removed.

## How it works

The existing `.day-tabs` navigation remains a horizontally scrolling row of date links. CSS applies `scrollbar-width: thin` and `scrollbar-color` with the accent and paper tokens, plus rounded WebKit scrollbar track and thumb rules. Smooth scrolling is disabled when the visitor requests reduced motion. The small JavaScript block still brings the selected date into view on load.

## Main design choice

Use the native horizontal scrollbar as the single visible scrolling control. The links remain usable with JavaScript off, and the strip needs no extra buttons or scroll state listeners.

## Problem and constraints

The previous strip showed left and right arrow buttons alongside a scrollbar and a mobile instruction. The base app requires plain CSS and vanilla JavaScript, and the seven-day booking window stays fixed.

## Alternatives considered

- Keep the arrows and hide the native scrollbar: rejected because the issue asks for a themed scrollbar in place of the arrows.
- Add a custom drag bar: rejected because a native scrollbar already supports mouse, touch, and keyboard scrolling.

## Trade-offs

Scrollbar visibility while idle follows the browser and operating system. The strip remains horizontally scrollable and the thumb and track colors are defined by the app tokens.

## Key parameters

- `.day-tabs` uses the existing `--c-accent` thumb and `--c-paper` track tokens.
- The WebKit scrollbar height is `0.4rem`.
- The seven date links and selected-day behavior are unchanged.

## Assumptions

The horizontal scrollbar and partial next date make the remaining dates discoverable without helper copy.

## Edge cases

- At both 1280 and 390 pixels, seven dates overflow the strip and it can scroll sideways.
- With JavaScript disabled, each date link still navigates to the chosen day.
- Reduced-motion preference turns off smooth scrolling.

## Breaks or needs follow-up

None.

## Traps

- Do not restore `.day-scroll` buttons, the `.day-scroll-hint` caption, or JavaScript arrow listeners.
- Keep the selected-date scroll positioning in `clinic-base/assets/booking-slots.js`.
- Keep the native date links in `clinic-base/book.php` for visitors without JavaScript.

## Components

- `clinic-base/book.php` removes the arrow buttons, helper caption, and obsolete `aria-describedby` reference.
- `clinic-base/assets/css/style.css` styles the native date strip scrollbar and removes arrow and caption styles.
- `clinic-base/assets/booking-slots.js` removes arrow listeners and state updates while keeping selected-date positioning.
- `tests/test_book_page.php` checks that the old controls are absent and the scrollbar token rules exist.
- `tools/ui/booking-controls.test.mjs` checks overflow, sideways scrolling, themed computed styles, reduced motion, date links, and both requested widths.

## Changes outside the scope

The PHP and browser tests and this required decision record are verification artifacts. No other application component changed.

## How it was verified

`node tools/ui/booking-controls.test.mjs` passed with JavaScript on and off at 1280 and 390 pixels. Saved before and after screenshots at both widths are under `UIPROBLEMS/after/iter8/204-booking-date-scrollbar/` and were visually inspected. `php tests/run.php` checks the full project suite.

## Not verified

Idle scrollbar visibility can vary with the visitor's operating system scrollbar settings.

## To change this

Adjust the native scrollbar rules in `.day-tabs` and keep the browser assertions in sync. Preserve the seven date links and reduced-motion behavior.

## Rollback

Restore the former arrows, caption, and arrow listeners together, and revert their matching tests.
