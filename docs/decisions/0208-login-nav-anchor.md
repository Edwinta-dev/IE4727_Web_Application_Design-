Status: implemented · Issue: #208 · Date: 2026-10-27

## In short

Guest navigation places Log in immediately after Register. The link opens the existing home login card.

## Problem and constraints

Guests on other pages lacked a direct navigation link to the login form. The page limit rules out adding a login page, and authenticated visitors should not see a login link.

## Main design choice

Use a normal fragment link to `index.php#login-card` and put that ID on the existing login section. This uses the browser's anchor navigation instead of adding a JavaScript scroll handler. The guest link stays in the shared navigation's default role list, while the patient, doctor and admin lists stay as they are. A local `scroll-margin-top` on the card gives the browser room to position the form below the header on narrow screens.

## How it works

The shared guest navigation renders Log in after Register. Its existing `url()` helper prefixes the app path while preserving the fragment. The browser navigates to the home page and scrolls to the ID on the login section. The CSS margin adjusts the anchor position without changing the layout.

## Breaks or needs follow-up

None.

## Alternatives considered

- A JavaScript scroll handler could calculate a precise midpoint, but would add code and make the link depend on scripting.
- A separate login page would exceed the fixed page budget and duplicate the existing form.

## Assumptions

The shared navigation's default branch represents guests, and the existing home login section remains the destination for signing in.

## Edge cases

At desktop width, the card is already near the top of the document, so the browser may have too little scroll range to place its exact midpoint at the viewport midpoint. On mobile, the offset leaves room above the card while keeping the form controls visible.

## Rollback

Remove the guest link, the section ID, and its scroll-margin rule together.

## Traps

- The navigation helper adds the app base path to internal links; keep the link in its existing URL convention.
- Keep the anchor on the section that contains the form so it works without JavaScript.
- A fixed header or short viewport can limit exact vertical centring; the full card and its controls must remain visible.

## Key parameters

- Fragment ID: `login-card`.
- Guest link destination before URL base conversion: `/index.php#login-card`.
- Scroll offset: `clamp(5rem, 20vh, 11rem)`.

## Components

- `clinic-base/partials/nav.php`: guest Log in link following Register.
- `clinic-base/index.php`: stable ID on the member login section.
- `clinic-base/assets/css/style.css`: scroll margin for the target.
- `tools/ui/login-nav-208.test.mjs`: Chromium checks guest link order, fragment landing and authenticated nav at 1280 and 390 pixels.

## Changes outside the scope

The browser regression test and this decision record are required verification artifacts. No other application component changed.

## Trade-offs

Fragment positioning depends on the viewport and the layout above the card. The card can sit slightly above the precise viewport midpoint when the document cannot scroll farther upward.

## To change this
