Status: implemented · Issue: #185 · Date: 2026-10-16

## In short
The Patient and Doctor registration forms now have the same gap between their last field and the Create account button.

## Main design choice
Keep the existing sliding role switcher. In `clinic-base/assets/css/style.css`, take only its inactive fieldset out of layout so the selected fieldset determines the track height. Both roles then inherit the existing `#registration-form` gap rule from `clinic-base/assets/style.css`. This wins over a smaller button margin because the taller, inactive Doctor fieldset would still hold the Patient button down. No registration markup or server behavior changes.

## How it works
The role switcher sets `aria-hidden` on the inactive fieldset. The CSS positions that fieldset outside the track's height calculation while retaining its horizontal position for the slide. When Doctor is selected, its fieldset occupies the right half of the 200% track. The active fieldset therefore sets the viewport height, and the form's existing gap applies after either role's last fieldset.

## Traps: why the obvious fix is wrong
- Reducing the form gap alone does not remove the blank area: the inactive Doctor fieldset is taller than Patient and still determines the flex track height.
- Hiding the inactive fieldset with `display: none` would remove the other panel from the slide transition and change the role switcher behavior.
- The Doctor fieldset needs its 50% offset when selected because the track still translates left by half its width.

## Components
- `clinic-base/assets/css/style.css`: role-scoped positioning of inactive fieldsets and selected Doctor offset.
- `tests/ui_issue185.mjs`: Chromium captures and last-field-to-button measurements at 1280 and 390 pixels.

## Breaks or needs follow-up
None known. The existing role switcher uses JavaScript to set `aria-hidden`, which the CSS selectors depend on.

## Problem and constraints
Issue #185 reports an oversized Patient form gap. `AGENTS.md` requires before and after screenshots and a visual check; no new pages, dependencies or transport changes are needed.

## Alternatives considered
- A smaller fixed button margin: rejected because it cannot compensate for the inactive Doctor panel's height at every width.
- Removing the sliding track: rejected because this would be a broader interface change than the issue requests.

## Trade-offs
The small CSS override is coupled to the existing role switcher's `aria-hidden` and 200% track geometry. Changing that switcher later requires checking this rule again.

## Key parameters
- Before: Patient 129.6 px, Doctor 43.6 px at 1280 and 390 px.
- After: Patient 43.6 px, Doctor 43.6 px at both widths.
- Browser acceptance allows at most 2 px difference and requires a 25–55 px gap.

## Assumptions
The Doctor gap already reflects the desired spacing, as the issue states.

## Edge cases
Role switching in both directions is covered by the existing registration switcher test; this test captures each role after switching to Doctor.

## Not verified
Screen-reader behavior was not tested with a physical reader.

## Changes outside the scope
`tests/ui_issue185.mjs` is the issue's browser regression test. This decision record is required by the repository's decision-record gate.

## How it was verified
`node tests/ui_issue185.mjs before` captured the original issue; `node tests/ui_issue185.mjs after` checks the corrected geometry and writes screenshots under `UIPROBLEMS/after/iter7/issue-185-create-account-spacing/`. `php tests/run.php` is the project regression suite.

## To change this
If the role switcher layout changes, inspect both roles at desktop and mobile width, then update the positioning selectors with the track geometry.

## Rollback
Removing the four registration positioning rules restores the earlier Patient blank space without changing saved data.
