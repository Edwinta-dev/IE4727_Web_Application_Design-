Status: implemented · Issue: #189 · Date: 2026-10-16

## In short
The Patient and Doctor choices stay visible, and only the arrow leading to the other choice appears.

## Main design choice
Use option A from the issue: hide the arrow for the selected role while keeping the existing native radio controls as labelled choices. This makes the current role and the available direction explicit without changing the form submission.

## How it works
`setRegistrationRole()` updates the arrow visibility whenever a radio choice or arrow changes the role. The CSS reveals the existing radio choices, marks the checked label, positions the remaining arrow, and draws a rounded focus ring on keyboard focus. Native radio arrow-key handling remains intact.

## Traps: why the obvious fix is wrong
- Leaving both arrows visible still presents a no-op control at either endpoint.
- Hiding the radio choices leaves only the heading to explain the selected role and removes a direct way to choose either role.
- Intercepting arrow keys on a focused radio prevents the browser's native radio navigation and focus movement.

## Components
- `clinic-base/assets/app.js`: hide the arrow targeting the active role and preserve native radio keyboard behavior.
- `clinic-base/assets/css/style.css`: show selected and unselected labelled choices, position the useful arrow, and style keyboard focus.
- `tests/ui_issue189.mjs`: reproduce the committed bug and exercise both roles in Chromium at desktop and mobile widths.

## Breaks or needs follow-up
None known.

## Problem and constraints
The previous switcher displays two arrows but only one changes the role. The base app must use local vanilla JavaScript and keep the existing registration page and server form.

## Alternatives considered
- Make both arrows toggle: valid option B, but a directional arrow would change meaning depending on the current state.
- Remove the arrows and use only radios: simpler, but the issue specifically allows the one-arrow interaction, which preserves the existing switcher.

## Trade-offs
The two labelled choices repeat the role heading, but make the available account types and selected choice clear before a user interacts.

## Key parameters
Patient shows the right arrow to Doctor; Doctor shows the left arrow to Patient. The visible arrow is a native button with an accessible label.

## Assumptions
The native radio controls are the primary keyboard choice controls; the visible arrow is a second, labelled button for the same transition.

## Edge cases
With JavaScript off, both radio choices remain available and the form still submits the selected role. A focused radio keeps native left and right arrow-key behavior.

## Rollback
