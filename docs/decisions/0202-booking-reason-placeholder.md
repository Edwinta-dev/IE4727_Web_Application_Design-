Status: implemented · Issue: #202 · Date: 2026-10-27

## In short

The empty Reason for visit field shows a muted example of the detail patients can enter.

## How it works

The existing text input has a native HTML placeholder. A scoped CSS rule colors its placeholder with the shared muted text token. The input remains empty until the patient types, so the example is not submitted.

## Main design choice

Use the browser's native placeholder behavior on the existing field. This gives an example inside the control and removes it when typing starts without changing form submission or adding JavaScript.

## Problem and constraints

The booking field did not show an example. The base app must retain its existing booking form and server submission. The UI should show the example at desktop and mobile widths.

## Alternatives considered

- Pre-fill the input value: rejected because an untouched example could be submitted as a visit reason.
- Add helper text outside the field: rejected because the issue requests an example inside the input.

## Trade-offs

The example is visible only while the input is empty. The existing visible label continues to identify the field after typing begins.

## Key parameters

- The example is `e.g. Cough and mild fever for 3 days`.
- `#reason::placeholder` uses `var(--c-muted)` and full opacity.

## Assumptions

An example of symptoms and duration gives enough guidance without asking for a diagnosis.

## Edge cases

- An empty field submits an empty reason in `FormData`, not the example.
- After typing begins, the placeholder is no longer shown.
- Rescheduling continues to display its existing read-only reason instead of the new input.

## Breaks or needs follow-up

None.

## Traps

- Keep `placeholder` separate from `value`; the example must never become booking data.
- Keep the existing `required` attribute and visible label.
- Scope the CSS rule to the booking reason field so other placeholders retain their current styling.

## Components

- `clinic-base/book.php` adds the native placeholder to the existing input.
- `clinic-base/assets/css/style.css` sets its muted placeholder color.
- `tests/test_issue161.php` preserves its markup assertion for the required reason field.
- `tools/ui/issue202.test.mjs` checks browser rendering and form data at both requested widths.

## Changes outside the scope

The PHP assertion, browser regression test, and this decision record are required verification artifacts. No other application page changed.

## How it was verified

`node tools/ui/issue202.test.mjs` checks the empty placeholder, computed color, form data, and typing behavior at 1280 and 390 pixels. `php tests/run.php` checks the project suite. Before and after screenshots are under `UIPROBLEMS/after/iter8/issue202-reason-placeholder/`.

## Not verified

The browser test does not submit a booking; it checks the serialized form value directly.

## To change this

Update the placeholder text in the existing input and its matching browser assertion together.

## Rollback

Remove the input placeholder and its scoped CSS rule, then remove the matching tests and this record.
